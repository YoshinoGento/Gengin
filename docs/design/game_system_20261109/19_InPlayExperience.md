# 通常プレイ画面からのシステム体験

更新日: 2026-11-11。実装・自動検証・Release Rebuild済み。新規UIの実画面確認は未完了。

2026-11-16追記: 大会開始と最終結果の4項目を追加し、現在は5分類20項目。以下の16項目に関する検証記録は11/11時点。追加分の仕様と確認状態は [大会開始からクリア](20_ContestClear.md) を参照。

## 目的と操作

展示で待ち時間や準備操作を減らし、既存のゲームシステムを実際に操作できるようにする。
外部ランチャーではなく、農場選択・通常HUD・農場メニューの「システム体験」から選ぶ。
分類、項目、開始、切替確認の順に進む。切替後のHUDには、その機能への操作ボタンを表示する。
メニューを閉じて同じ農場を続けることも、別項目へ切り替えることもできる。

## 初めて見る人への説明

一覧の上に「水路と土を整え、よい野菜を育てるゲームです」とだけ表示する。
右側は選択中の1項目に限定し、目的・「まず：」の操作・「注目：」の観察対象の3行に揃える。
一覧側には名前だけを残す。16項目の説明を同時に並べず、操作方法の長文や追加の説明ダイアログも増やさない。
開始ボタンの前に使用モードを明示し、切替確認中は説明を隠して未保存変更の注意に集中させる。

雨は雨天の準備済み農場で給水を止め、見た目・音・土の水分を見る体験である。天候切替ボタンは未実装。
防虫は予防であり既存の害虫を駆除しない、駆除後も受けた被害は残る、土の養分を増やしても品質は栽培して確認する、という制約も該当項目の1行に含める。
固定の説明であり、操作済み・達成済みを自動判定するガイドではない。ゲーム数値と保存処理は変更していない。

| 分類 | 項目 | 用意する状態 |
|---|---|---|
| 栽培と売買 | 種まき、収穫、土づくり、売却・保護 | 耕作済みの畑と3種の種、成熟3作物、低栄養の空き畑、保護付き在庫 |
| 水と環境 | 水源・水路・高低差、雨、害虫、防虫・拡散 | 既設水路、雨天、発生中の害虫、防虫を置ける空きマス |
| 大会と成長 | 時間送り、品評会、審査結果、土地拡張 | 成長中の作物、10日目の予約済み野菜、実採点した結果、21日目の拡張可能農場 |
| 記録と支援 | 作物図鑑、生育比較、救済、保存 | 3作物の収穫記録、水分の違う2マス、資金・種切れ、別名保存できる農場 |

初期配布農場はフリー。雨・害虫・防虫拡散・時間送り・品評会・結果・段階拡張の例は既存大会ルールを使う。
普通のフリー農業に勝手に害虫や大会を追加しない。選択画面に使用ルールを表示する。
音量設定・セーブ画面へは体験メニューの下部から移れる。台風など未実装の案は含めない。
各例は意図的な準備状態であり、初見プレイヤーの自然な進行・バランス測定結果ではない。

## 責務と処理順

- `FarmExperienceSystem`: 固定16件のカタログ、範囲検証、同梱ファイルの選択。通常ゲームの数値は直接変更しない。
- `FarmDocumentSystem::LoadPrepared`: 1MiB以下の同梱データを通常と同じ検証経路で読み、未保存の農場として適用する。正常な通常ロードはID照合を維持する。
- `GamePlaySessionSystem::Execute`: 既存Bridge要求を受け、ロード成功後に道具・履歴・プレビュー・比較・一時描画・給水・Timelineを同期する。
- `FarmRuntimeController` の専用実装ファイル: 選択と確認、メニュー移動、既存Actionへの短絡導線を管理する。
- `FarmExperienceView`: 名前・目的・最初の操作・観察対象・ルール・確認を表示し、Requestを通知する。ゲーム状態の変更は行わない。

処理順は、項目選択 → 確認 → 読込と全データ検証 → System適用 → 一時状態の初期化 → 通常プレイ。
確認中は他の操作要求を遮断し、確認要求は処理前に消費して二重ロードを防ぐ。
品評会の操作は既存の展示台→出品画面のActionを通す。審査点や結果をUIで捏造しない。
Game/Sceneへの責務追加、DX12 Pass追加、Debug画面追加はしない。

## 保存と所有権

- 切替前に、未保存の変更が失われる旨を確認する。必要な変更は先に保存する。
- 切替成功時はactive ID/pathを空にし、dirtyな未保存コピーにする。通常セーブとcatalogは書き換えない。
- 体験中に通常の上書き保存はできない。保存画面で別名保存すれば独立した農場として残せる。
- 別名保存後はその場では体験への短絡ボタンを維持する。通常ロード・初期化・リセットでは体験状態を解除する。
- 終了時に体験状態を自動保存する変更はしていない。保存済みの元農場は通常ロードで戻せる。
- 不正ID、欠損・未対応schemaのファイルは読み込まない。固定カタログからのみUIで指定できる。

## アセットの再生成

### 文字画像とEXEの一致

文字画像 `farm_runtime_menu.png` と生成ヘッダ `FarmRuntimeLabels.h` は一組。
文字変更で画像内の配置が変わるため、画像だけ更新して古いEXEを動かすと、文字の欠け・隣の文章の混入・数字の文字化けが発生する。
生成後は実行中のゲームを終了してReleaseをビルドし、EXEとResourcesを一緒に配布する。

- 生成ヘッダに画像のbyte数・FNV-1a fingerprint・SHA256のcontract文字列を出力する。
- RuntimeUIは初期化時、固定4KiB bufferでbyte数とfingerprintを照合し、不一致ならGPU資源を作る前に失敗を返してLoggerへ記録する。改ざん防止ではなく誤った組み合わせの検出。
- 梱包スクリプトはPNGのSHA256とEXE内のcontractを出力前・コピー後に照合する。古いEXEのまま出力しない。
- フレームごとの照合、描画数・GPUテクスチャ数の追加、セーブ変更は行わない。UI生成後にResourcesを差し替える運用は非対応。
- runtime_viewテストは正常・内容変更・欠落・余分なbyte・空・存在しないファイル・I/O失敗を検査する。レイアウトテストだけではEXE/PNGの混在は検出できない。

`run_farm_campaign_balance_test.cmd --export-exhibit` で通常Systemを使った7つの基礎状態を生成する。
次に `run_farm_experience_test.cmd --generate <exportedRoot> project/Resources/farm/experience` で16例を準備し、製品のSaveAsとLoaderで往復検証する。
`tools/ui/prepare_system_experience.ps1` は生成したフリー農場だけを初期記録としてコピーする。元のSettings・既存配布フォルダは参照/上書きしない。
外部ランチャー版 `prepare_system_exhibition.ps1` は以前の試作であり、今回の最終導線ではない。
