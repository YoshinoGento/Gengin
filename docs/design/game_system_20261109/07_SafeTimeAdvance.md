# 安全な時間送りとDebug確認

更新: 2026-11-10。通常農場へ接続済み。独立テスト用と現在の農場用の2種類のDebug画面を用意。長時間・負荷・全画面遷移の組合せは未確認。

## 目的と範囲

収穫・水不足・水分過多・大会・害虫予兆で止まる時間送り。単に日付だけを変更しない。既存のフリーモードは対象日なしとして停止する仕様を維持する。天候は未実装なので、この時間送りでも再現しない。

## 独立サンプルの確認手順

1. `project/CG2_00_01.sln`を開き、スタートアップを`CG2_00_01`、構成を`Debug / x64`にしてF5。
2. 上部の「ウィンドウ → 安全な時間送りテスト」を開く。タイトルからでも使える。
3. 上段のケースを選び「安全な時間送りを開始」を押す。
4. 停止理由・日付・水分・成長・害虫の予兆日・被害日数を確認する。
5. 「同じケースを最初から」で再現。「1回だけ進める」は最大64回の固定更新だけ進める。

選択中のケース名と停止理由を表示する。手動更新後は「手動更新待ち」となり、自動では進まない。水分と成長は小数点以下2桁まで表示し、収穫直前の99.99%と収穫可能な100.00%を区別する。

| ケース | 期待する結果 |
|---|---|
| 害虫の予兆 | 5日目の終了直前から6日目へ。予兆日6、被害日数0で停止 |
| 収穫直前 | 成長100%で「収穫できます」と停止 |
| 水不足 | 時間を進める前に水やりが必要と表示 |
| 水の与えすぎ | 時間を進める前に水分過多で停止 |
| 大会の前日 | 9日目の終了直前から10日目0秒で停止 |
| 空の畑・取消 | 自動送り中に取消可能。手動1回送りは64更新後に待機 |

テスト画面を閉じたり他アプリへ移った場合は停止する。通常農場・元のセーブ・提出物は変更しない。これは特定の状態を作った検証データであり、通常プレイの難度の証拠ではない。

## 現在の農場を使ったDebug確認

1. Debug / x64でゲームを開始し、通常農場へ進む。
2. 「ウィンドウ → 現在の農場：時間送り」を開く。
3. 「1回だけ進める」で最大64更新だけ進め、日付・秒数・更新回数を見る。次に押すまで待機する。
4. 「安全な時間送りを開始」で自動更新。「時間送りを取り消す」で停止を維持する。
5. 水不足・過湿・収穫・害虫などで止まった場合は、「停止理由の畑を選択」で対象マスを選ぶ。
6. 「通常の時間経過に戻す」で時間送りの停止を解除する。エディター上部の一時停止は別なので、止めている場合は上部の再生も押す。

大会で止まった場合は、畑インスペクターの「大会案内を閉じて時間を進める」でも再開できる。案内の解除が成功した場合だけ再開コマンドを送る。

こちらは**現在の農場を実際に変更する**。自動保存はしないが、後から保存すればその状態が残る。元のデータを守る確認には、新規農場か別コピーを使う。

パネルのXと「ウィンドウ」メニューからの非表示はいずれも取消。フォーカス喪失、メニュー・仮配置・時間巻戻し・文書操作などでも自動送りを止める。取消後に以前の速度へ自動復帰させない。

## 通常版の操作

- 右側のカレンダーアイコンから開始。ホバー時に操作名を表示する。
- 実行中は同じ位置が取消アイコンになり、上部に「時間送り中」を表示する。
- 停止後は上部に理由を表示。対象マスがある場合は理由欄から選択できる。
- 上部の再生ボタン、または1/2/4倍指定で通常の時間経過へ戻る。
- 大会案内の「畑で準備」は停止維持。「案内を閉じて時間を進める」は通常の時間経過へ戻る。
- フリー農業モードは待機目標を未定義のため、このボタンは無効。通常の1/2/4倍は利用できる。

## 責務と更新順

- `FarmSimulationStepSystem`: 通常更新と時間送り共通の同期処理。生育比較の事前観測 → 水分 → 成長 → 比較の事後観測 → 日付/大会 → 害虫 → シーズン判定。借用参照を呼出し後に保持しない。
- `FarmTimeAdvanceSystem`: 各更新の前後で停止条件を判定し、共有Stepを呼ぶ。害虫有効時は各日の境界で区切り、予兆から被害日を飛び越えない。
- `FarmTimeAdvanceControlSystem`: セッション内の開始・手動送り・取消・停止維持を管理。1描画フレームに最大1バッチ。同じフレームの通常FixedUpdateを抑止する。
- `GamePlaySessionSystem`: 依存Systemとブロック状態を渡す。進行したバッチでは履歴を破棄し、DirtyとTimelineを更新する。
- `FarmTimeAdvancePlaytestSystem`: 独立したGridと各Systemを所有。ケース初期化・操作の再検証・1フレーム1バッチ更新を担当する。コピー禁止。
- `FarmTimeAdvanceTestWindow`: 読み取り用Viewを表示し、Requestを返すだけ。UIで農場の値を変更しない。
- `FarmTimeAdvanceLiveWindow` / `FarmTimeAdvanceView`: 読み取り用の状態を表示し、操作を通知するだけ。
- `EditorShell` / `FarmRuntimeController`: 操作を既存Bridgeへ配送する。UIに育成計算は持たせない。

1バッチ64更新、1セッション120000更新の上限は既存の`constexpr`を使用。判定とView生成でGrid全体をコピーしない。進行したバッチのTimeline記録には既存のスナップショット処理を使う。追加のTexture/Buffer、Descriptor、Barrier、Fenceはなく、既存ラベルAtlasを再生成した。DebugのImGui描画は増える。CPU/GPU時間は未計測。
