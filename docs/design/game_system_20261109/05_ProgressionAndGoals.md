## 1. 次に何をするかの案内

**SYSTEM-02 初回実装 (2026-11-09):** 通常農場の上段に「次の目標」を1件表示する。普段は短文だけ。説明があるときは上段の案内にカーソルを合わせると補足が出る。大会の案内に付く `D10` などは開催日。案内自体から自動で作業・出品しない。

- 通常HUD内の優先順は、害虫、開催2日前以降で未完了の大会準備、選択中の畑の作業。「予約済み」は育成待ちまたは畑が未選択の場合だけの確認表示とする。既存の大会当日ダイアログやメニューはそのまま。期限内の在庫・予約がない場合に提出を促さない。
- 畑の案内は既存の水分評価、種の解放・在庫・価格、売却可能な在庫、収穫物の空きを参照する。適量の水分で成長待ちでも、時間停止中なら再開を案内する。
- Debug x64の「ウィンドウ → 次の目標テスト」で17の事例と、独立した1マスの操作サンプルを選べる。通常農場、セーブ、害虫テストには触れない。
- `FarmNextGoalSystem::Inspect` は既存Systemから事実を読み取り、`Evaluate`が案内を選ぶ。Controllerは現在のモード・選択作物・水分評価などのContextを渡し、Viewは選ばれた内容を表示する。出品の権限やセーブ形式は変更しない。
- 在庫確認は大会が近い場合に限り、既存の在庫上限まで。新規のDX12パス、Descriptor、Barrierは追加せず既存のSprite Atlasと描画枠を再利用する。描画予算とHUDの重なりは構成テストで確認済み。実機での読みやすさは別途確認する。

### Debugでの確認手順

最新確認（11/10）: Debug viewport座標をタイトルの1280x720へ変換する修正後、全Debug再ビルド版でクリックと操作サンプルを確認。Release通常農場で購入→植付け→水やりとHUD案内が対応することを確認し、両版とも終了コード0。以前の中間ビルドで発生したCRTメモリ破損は今回の各1回の検証では再発しなかったが、原因の特定・長時間の安全性保証とは別。上記の未確認記述は当時の結果。

1. 独立コピーの `generated/codex_checks/next_goal_debug_review_20261110/StartGame.cmd` を起動する。通常開発では `project/CG2_00_01.sln` を開き、スタートアッププロジェクトを `CG2_00_01`、構成を `Debug / x64` にしてF5で起動する。
2. エディター上部の「ウィンドウ → 次の目標テスト」を開く。
3. 「事例一覧」タブで次の4例を選び、案内が切り替わることを確認する。

| 選ぶ例 | 確認する内容 |
|---|---|
| 予約済みだが水やりが必要 | 予約済みの表示ではなく、水やりを案内する |
| 予約済みだが時間が停止中 | 時間の再開を案内する |
| 自動給水中で水分過多 | 「次：自動給水を切る」と表示する |
| 自動給水なしで水分過多 | 自動給水の停止ではなく、水やりを控える案内にする |

「事例一覧」は読み取り専用の判定例。例の成功と、実プレイで迷わず操作できることの確認は別に扱う。

4. 「操作して確認」タブで「新しいテスト農場」を押す。所持金60G、種0個の独立した1マスが始まる。
5. 大きな「次の確認操作」ボタンを押すと、その時点で実行可能な「耕す→買う→植える→水やり」へ変わる。下の2列のボタンでは各操作を個別に試せる。説明の長さでボタン位置は動かない。
6. 「育成を停止」で時間再開の案内と育成ボタンの無効化を確認し、再開する。
7. 水分を保ちながら「育成を5秒進める（検証用）」を押す。成熟したら収穫し、資金不足のため売却を促す案内から、売却後の種購入案内への変化を確認する。
8. 「テスト状態の作り直し」を開き「種なし・資金なしを再現」で購入・植付け・売却が無効になることを確認する。「新しいテスト農場」で戻せる。

**この5秒送りはサンプルの育成だけ。日付・害虫・大会は更新しない。SYSTEM-03は別のDebug画面に加え通常プレイにも接続済み。** 両タブとも元の農場を書き換えず、保存しない。

以下は初回実装前の設計メモ。

現状でも開始目標、給水の説明、段階解放の案内はある。足りない候補は、農場の現在状態から次の一手を継続して示す仕組み。

例: 「種を買う」→「畑を耕す」→「水が届くか確認する」→「育てる」→「成熟した作物を収穫する」→「売るか大会用に残す」。固定順の強制チュートリアルではなく、すでに達成した項目は飛ばす。

表示は短い主目標1件と、必要時だけ開く詳しい理由に分ける。大会が近いときは期限と未出品を優先する。「虫の予兆」など緊急情報との優先順位もSystemで決定する。

完成条件: 新規農場・種なし・給水失敗・収穫可能・大会予約済みで、矛盾した指示や不可能な操作を出さない。

## 2. 安全な時間送り

11/10: 害虫停止・独立Debugケース・通常農場への接続を実装し、自動テスト・両構成ビルド・基本操作の画面確認まで完了。長時間・全操作経路の組合せ確認は残る。現在の詳細は[安全な時間送り](07_SafeTimeAdvance.md)。以下は初期提案。

`FarmTimeAdvanceSystem`はあるが、通常プレイから呼ぶ経路が不足している。1/2/4倍速と区別し、「次の変化まで待つ」という操作を提案する。

収穫可能、水不足/過多、大会、将来の害虫予兆で停止させる。新しい害虫や天候を足した後に、古い停止条件のまま接続してはいけない。現在の実装はフリーで対象なしとなるため、フリーにも公開するなら待つ対象の仕様変更が必要。

完成条件: 通常の細かい更新と同じ結果になり、対応が必要な瞬間を通過しない。UIが固まらず取消可能で、実行中に操作対象が変わっても古い参照を使わない。

## 4. 養分と堆肥の選択

養分の消費と植付け前の堆肥はあるが、堆肥の購入費用・種類などはない。無料で毎回補充するだけなら、選択ではなく定型操作になりやすい。

提案: まず肥料を何種類も増やすより、「補充に資金を使う」「安い作物で回収する」「大会用の畑に集中する」の判断を成立させる。価格は種・収穫売上と合わせて検証し、旧農場の資金を急に減らさない。

## 5. 記録・図鑑・繰り返し遊ぶ目標

新しいDebug画面は作らない。実画面の使いやすさは未確認。入賞履歴は既存の大会結果で扱い、プロフィール全体の図鑑・報酬・トロフィーは今回追加しない。

## 6. 違う条件の農場

学校資料の複数ステージを取り入れるなら、外観違いを量産しない。

候補は「水源が一つで配分を考える農場」「段差が多い農場」「乾燥条件の農場」。同じ操作でも水路の組み方が変わることが条件。地形保存は既存機能だが、達成条件・解放・ステージ選択とは別。

まず固定配置で攻略可能性を確認し、自動生成はその後。生成しただけで水が届かない、必要な作物を植えられない配置を排除する検証が必要。

## 7. 資金不足からの立て直し

所持金0だけでゲームオーバーにしない。種・生育中の作物・売れる在庫があれば再開できる。

新しい案として、すべて失った場合に少量の基本種を受け取る救済を検討する。回数制限や大会評価との関係を決め、受取とロードを繰り返して無制限に増やせないようにする。借金・経営破綻は現状の確定仕様ではない。

## 優先順位の判断

**最初は害虫への対応を品質・大会までつなぐ。次に短期目標と待ち時間を整える。天候、ランク・拡張はそれぞれ独立して検討する。**

新機能で情報が増えるほど、今まで改善したUIを再び複雑にする危険がある。新しいシステムは、追加の常設パネルではなく、畑の状態と必要時だけの説明を基本にする。
