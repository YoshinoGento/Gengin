# 農場ランクと土地拡張

更新: 2026-11-10。通常ゲームへの接続を実装。実機操作と30日通しの調整は未確認。

## 1. 目的とルール

収穫を売った実績が、より広い農場を使う目標につながるようにする。所持金を使うとランクが下がる仕様にはせず、確定した売上を別に累計する。

| 累計売上 | 農場ランク | 拡張可能な面積 |
| --- | --- | --- |
| 0G | 1 | 5×4 = 20マス |
| 500G以上 | 2 | 5×5 = 25マス |
| 1,500G以上 | 3 | 5×6 = 30マス |

- 数値は初期調整値。大会30日間での到達時期・難度を検証した値ではない。
- フリー農業・大会の両方で利用可能。終了済みの農場は変更不可。
- 拡張は無料・任意。自動では広げず、1回の操作で5マス追加する。
- 売却のプレビュー、保護中・予約中の収穫物、失敗した売却は加算しない。
- 種の購入などで所持金が減っても累計売上は減らない。
- 作物・土地の高さの段階解放、大会得点・総合ランクは変更しない。

## 2. 通常メニューからの操作

1. 農場メニューを開く。
2. 農作業または土地・水路の簡易メニューで「農場ランク・土地拡張」を選ぶ。土地・水路の詳細メニューにも入口がある。
3. 現在のランク、面積、累計売上、次のランクまでの残額を確認する。
4. 解放済みなら「５マス広げる（無料）」を選ぶ。追加費用は発生しない。
5. 通常の保存操作で記録する。拡張のみでは自動保存しない。

幅5以外や高さ4～6以外の編集用農場、Preview中、タイムライン参照中は拡張しない。拡張自体はUndo対象外で、拡張前のUndo/Redoとタイムライン履歴をクリアする。

## 3. 処理と責務

1. `FarmEconomySystem::SellMatching` が売却確定後に `lifetimeSales` を加算する。上限は `INT_MAX` に飽和させる。
2. `FarmDevelopmentSystem` が累計売上からランクと拡張可否を導出する。ランクそのものを別保存して不整合を作らない。
3. `FarmDevelopmentView` は表示と要求通知だけを行う。
4. `FarmRuntimeController` が要求を `GamePlayEditorBridge` へ渡す。SessionはPreviewなどの状態を検査する。
5. `FarmDevelopmentSystem::Expand` がGridの世代と高さを再確認し、行を末尾へ追加する。既存のタイル番号・水分・生育・養分・害虫・水路を保持する。
6. `FarmGrid::ReplaceSnapshot` は全データを検証し、コピー成功後に寸法と配列を入れ替える。通常Undo用の `RestoreSnapshot` は従来どおり寸法一致が必要。
7. Sessionが古い履歴・比較・収穫演出をクリアし、給水とタイムラインを再構築、未保存状態へ変更。Controllerがカメラを農場全体へ戻す。

既存のScene/Game/UIへ売上計算や農地変更ロジックは追加しない。Gridは中央基準なので、拡張後は既存セルのワールド位置がずれる。番号と内容は保持するが、見た目・プレイヤー位置との関係は実機での確認が必要。

## 4. 保存と背景

- 保存形式はschema21。累計売上と拡張寸法を保存する。
- schema20以前は累計売上0Gとして読む。所持金から過去の売上を推測しない。
- 標準農場同士では5×4～5×6の異なる寸法をロードできる。その他の編集用サイズは従来どおり寸法一致が必要。
- 不正な寸法、タイル数、累計売上の型・範囲は、実データへ反映する前に拒否する。
- 標準農場を最初からやり直すと20マス・累計売上0へ戻る。
- 背景の草と下地の除外範囲を最大30マスに合わせる。拡張後も背景を表示する。
- 30マスで従来の地形部品上限640を超える組合せがあるため、最大32部品×30マスの960へ変更する。既存のObject保持方式・描画パス・GPU同期方式は変更しない。

- 売却境界、保護・予約、金額上限、ランク境界、連続拡張拒否、データ保持、拡張先の水路給水を自動テスト。
- 拡張保存の読込・初期化、旧形式、不正値の原子的拒否を自動テスト。
- 30マスの8種類の地形配置を検査。今回の最大は660部品で、960上限内。背景の除外範囲と有限な座標・正の寸法も検査。
