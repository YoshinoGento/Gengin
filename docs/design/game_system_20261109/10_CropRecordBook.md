## 遊びの目的と通常操作

大会や売却で野菜を手放したあとも、「次はもっと高品質にする」「大きさの自己記録を更新する」という目標を残す。

1. 農場で野菜を収穫する。
2. 農場メニューの概要から「この農場の収穫記録」を開く。
3. ニンジン・トマト・カボチャの最高品質、最大重量、収穫した種類数を確認する。
4. メニューの戻る操作または農場への復帰で栽培を続ける。

- 記録は農場ごと。別セーブや別プロフィールとは共有しない。
- 全3種類を収穫するまでは収集を案内し、達成後は品質・重量の自己記録更新を案内する。未解放の作物を今すぐ植えるようには指示しない。
- 品質と重量は、それぞれ別の野菜で達成した最高記録でもよい。同じ個体の成績とは扱わない。
- 品質は既存の100点満点の値。重量は大会と同じゲーム内換算であり、物理計測値ではない。
- 未収穫・重量不明は `--`。実際に品質0点だった収穫とは区別する。
- 作物の種類、採点、売値、解放条件は変更しない。新たな報酬やトロフィーは付けない。

## 記録を残すタイミング

| 操作 | 記録への反映 |
|---|---|
| 収穫 | 現在の収穫物一覧から表示する |
| 収穫のUndo / Redo | 一覧の取消・復元に追従する。取り消した収穫だけの記録を残さない |
| 売却プレビュー・失敗 | 永続記録を更新しない |
| 売却確定 | 実際に売った個体の品質・サイズを固定長の記録へ合成する |
| 保護中・出品予約中 | 売却除外の既存ルールを維持する |
| 大会への出品確定 | 既存の大会結果に保存された個体情報から表示する |
| 保存・読込 | 売却済み記録と既存の在庫・大会結果を保存し、表示を再構成する |
| 農場の最初からやり直し | その農場の記録も初期化する |

収穫時に別の永続記録へ即時追記すると、Undo後も未収穫のはずの記録が残る。そこで、**売却済み記録 + 現在の在庫 + 大会結果**の3つから表示を作る。

## 責務と保存

| 担当 | 責務 |
|---|---|
| `FarmCropRecordSystem` | 正式3作物の固定長記録、値の検証、最高品質と最大サイズの合成 |
| `FarmEconomySystem` | 売却確定時だけ記録を変更し、Snapshotに含めて所有する |
| `FarmRecordBookSystem` | 在庫と大会結果を合わせ、表示用の読み取り専用Viewを作る |
| `FarmRecordBookView` | 行・数値・未記録表示を組み立てる。採点や状態変更はしない |
| `FarmRuntimeController` | メニュー要求の検査、ページ切替、SystemとViewの仲介 |
| `FarmDocumentSystem` | schema22の保存・読込、旧版移行、不正ファイルの適用拒否 |

`economy.soldCropRecords`は必ず3要素とし、作物の順序、型、品質0～100、有限なサイズ値を検査する。未知の重量に非0値を入れたデータなども拒否し、読込失敗時は現在の農場を変更しない。

旧保存（schema21以下）は、残っている在庫と大会結果からのみ復元する。すでに売って失われた個体の成績は復元できない。新形式で保存すると、旧バージョンの実行ファイルでは読み込めなくなるため、旧版に戻す際は元のバックアップを使用する。

## 安全性と描画負荷

- 表示用の計算は記録3件、在庫最大128件、大会結果最大3件に限定する。毎フレームのGridコピーや新しい永続ポインタを持たない。
- `GetHarvestRecord`のnull、配列の範囲、無効な作物、未初期化・非有限の数値を確認する。入力値の検証はUIに分散させない。
- 文字は既存のSprite Atlasを再利用する。固定幅で余白の多かった配置を可変幅の行詰めに変更し、567項目を3840×1808へ配置した。変更前は560項目・3840×4076。
- AtlasのIDと参照方式は維持し、文字の領域内収容・最大幅・最大高さを生成時に検査する。新しい描画パス、Descriptor、Resource Barrier、Fenceの処理は追加しない。
- 記録帳の文字描画は増える。CPU/GPU時間、DrawCall総数、VRAMの実測はしていないため、性能改善率は主張しない。
