# 栽培の再開支援

更新日: 2026-11-10 / SYSTEM-11

## 目的と通常操作

種も購入資金もなく、作物からの収入も得られない状態で、農場を最初からやり直さずに栽培を再開する。

1. 農場メニューの「農作業」から「栽培の再開支援」を開く。
2. 条件を満たしていれば「種を1個受け取る」を押す。
3. ニンジンの種が1個増え、選択作物もニンジンになる。畑へ戻り、耕したマスに植えて水を与える。

対象の状態では、農場上部にも「種がないとき：再開支援」を表示する。新しいDebug画面は追加していない。

## 受取条件

次の条件をすべて満たした場合だけ受け取れる。

- 通常の農場操作が可能で、ニンジンが解放済み。
- 使用可能な解放済み作物の種を持っていない。
- 農地に作物が残っていない。成長途中・成熟済みの両方を含む。
- 収穫在庫がない。売却保護・大会予約・旧形式の在庫も含む。
- 解放済みのどの種も買えない。
- その農場の日付で、まだ支援を受け取っていない。

支援は**農場内の1日につきニンジンの種1個**。現金の支給・借金・大会点の変更はしない。残っている作物や在庫で立て直せる場合は、栽培・購入・在庫確認へ案内する。保護した収穫物を勝手に解除・売却しない。日付が翌日になっても、種や作物が残っていれば追加受取はできない。

旧TestCropや未解放の種は、通常栽培に使えないため受取を妨げない。受取前の保存へ戻った場合は、その保存全体へ戻る。別の保存の所持品を合算する機能はない。

## 責務と処理順

| 担当 | 責務 |
|---|---|
| `FarmRecoverySystem` | 現在の状態から受取可否を判定し、確定時に再検証する |
| `FarmEconomySystem` | 種と最終受取日を一緒に更新し、在庫generationを進める |
| `FarmDocumentSystem` | 受取日を保存・検証し、旧保存を移行する |
| `GamePlaySessionSystem` | System呼出し、作物選択、履歴破棄、Dirty通知を統括する |
| `FarmRecoveryView` / Runtime UI | 理由と次の操作を表示し、入力をCommandで通知する |

表示 → Command発行 → 日付・在庫/農地generationと最新条件を再確認 → 種を付与 → 過去のUndo・比較・タイムラインを初期化 → 未保存状態にする。

二重クリック、表示後の状態変化、日付の巻戻し、Preview・タイムライン操作中などで古い判定を使わない。Game/Sceneへ救済ルールを置かず、UI自身は所持品を変更しない。

## 保存と安全性

- 保存形式はschema25。`economy.lastRecoveryDay`を追加し、旧保存は未受取の0として読む。新形式は古いEXEでは開けない。
- 負数、非整数、範囲外、保存日より未来の受取日を拒否する。不正な読込で現在の農場を部分的に書き換えない。
- 判定は既存Grid/在庫への読み取りのみ。Gridコピーや判定ごとの動的確保を増やさない。
- 新しい3D描画、Render Pass、Descriptor、Barrier、Fence管理は追加しない。既存UIのラベルatlasを更新する。
- 種の種類・個数は`constexpr`。今回は調整用JSONや新しい管理画面を増やさない。

## 確認結果

- 専用テスト: 受取・連打・日付制限・逆行・最大日付、種価格境界、解放状態、栽培/成熟、保護/予約在庫、古い要求、植付けとUndo/Redo、schema25保存/復帰、旧schema24移行、不正保存8例を確認。
- 関連15スイート成功: recovery、runtime_view、development、record_book、repellent、pest_spread、free_mode、stage_progression、weather、time_advance、crop_size_document、care_history、formal_crops、trade、play_loop。
- Release x64の全Rebuild成功。Debugは今回再ビルドしていない。
- 独立した検証農場で、HUDと通常メニューの入口、受取0→1個、重複受取の無効化、通常植付け1→0個、栽培中の受取禁止、保存を画面確認した。
- デバッガーなしで再起動し、植えたニンジンと所持金0を読み込み、通常農場に戻れることを確認した。保存JSONのschema25・最終受取日1・残り種0も確認。検証版だけを閉じ、ウィンドウが消えたことを確認した（最後のプロセス終了コードは未取得）。

初回の増分ビルド版では、タイトルから農場への遷移でアクセス違反が発生した。全Rebuild後の同じ検証コピーは受取・植付け・保存まで進み、デバッガー下で終了できた。ただし、古い中間生成物の混在が原因だったとは確定していない。この観測だけで過去のメモリ破損問題も解消したとは扱わない。

元の設定・セーブ20ファイルは作業前後のハッシュが一致し、提出ZIPも変更していない。初見の使いやすさ、30日通しの収益バランス、全メニュー組合せ、長時間プレイ、別PC/GPU/DPIでの確認は残る。
