# 大会開始からクリア・展示確認まで

更新日: 2026-11-16。実装・自動検証・Release全Rebuild済み。実画面操作は未確認。

## 遊び方

農場開始画面の「大会を初日から始める」を選び、開始・切替確認を行う。
1日目、300G、5x4マスの新規大会になる。「この農場でプレイする」から開始する。
10日目・20日目・30日目に育てた野菜を出品し、最終大会で85点以上を取るとクリア。
途中の目標点は65点・75点。最終回に届くまでは、途中の不合格だけでゲーム終了しない。
提出の予約だけでは審査されない。出品画面で実際に提出する必要がある。

## 展示で短時間に確認

農場開始画面の「展示：クリア直前から」、またはシステム体験の「大会・クリア」を使う。

| 項目 | 用意する状態 | 確認すること |
|---|---|---|
| 大会を初日から始める | 新規の段階解放あり大会 | 開始、目標表示、通常の栽培 |
| 展示：最終出品・クリア | 30日目、出品予約済みの良質なカボチャ | 左上の出品操作から提出し、審査とクリアへ |
| 展示：目標点未満 | 30日目、品質の低い予約済みカボチャ | 同じ提出操作で、不合格の終了へ |
| 展示：未出品で終了 | 31日目、最終回未提出 | 未出品の演出、終了結果へ |

展示用の作物は人工的な準備データ。自然栽培の速さやバランスの測定結果ではない。
大会当日の案内が出たら「出品画面へ（停止を維持）」を選ぶ。農場画面からは左上の出品操作でも進める。
提出は本番のSystemを通し、提出前から成功フラグを立てたり、UIで審査点を変更したりしない。
結果から農場確認・タイトル・再挑戦へ進める。体験農場ではシステム体験にも戻れる。
農場確認は終了後の閲覧であり、そのまま大会の時間進行が再開するわけではない。
切替前の未保存変更は失われるため確認を必須とし、キャンセル可能。
保存済みの元農場・体験原本は上書きしない。新規大会や体験の継続保存は別名保存を使う。

## 設計と互換性

- FarmExperienceSystem: 5分類20項目の固定カタログと既存LoadPreparedへの委譲。
- FarmDocumentSystem: 通常と共通の完全検証、準備済み農場の適用、保存先の分離。変更なし。
- FarmRuntimeExperience: 入口、確認、ロード後の画面状態初期化と既存Actionへの通知。
- FarmContestOutcomeSystem: EndingをPending/Cleared/Failed/Missed/LegacyCompletedに分類する。
- FarmContestOutcomeView: SystemのEndingに対応する見出し・成功表現を表示する。

保存互換性のため既存のProgression::clearedは「セッション終了」を維持する。
失敗時もtrueになる既存値を成功判定に流用しない。成功は保存済み審査結果と段階目標から導出する。
旧来の段階解放なし大会には、新しい成功判定を勝手に適用しない。
ゲームクリアの条件や点数計算、天候・害虫・給水の数値、保存schemaは変更していない。
新規大会だけ到着演出・開始確認を残し、展示用の最終回は準備待ちを省く。

## 検証

- experience: 20項目、初期状態、通常提出、二重提出拒否、84/85点、元セーブ不変、別名保存・再読込、欠損/不正データ拒否。
- outcome: 128通り、120箇所の演出省略位置、成功/失敗/未出品/旧版のラベル、再挑戦の保存分離・I/O失敗。
- runtime_view: 20項目x確認/失敗の80状態、文字寸法・重なり・範囲、入口のHit領域、atlas整合性。
- campaign_balance: 実Systemの18通し条件。自動操作による栽培・天候・害虫・出品・取引を使用する。

## 安全性と保留

新規の所有ポインタ、GPU buffer、Descriptor、Barrier、Fence、Render Passは追加しない。
メニューの固定配列と選択範囲を検証し、Endingは初期化済みの値として保持する。
読込時の既存JSON/農場コピーはあるが、今回の状態分類に毎フレームの動的確保はない。
atlasは既存1枚を3840x2396へ更新。DrawCall・VRAM・CPU/GPU時間の実測はしていない。
既存Controller/Documentの大きさは設計負債として残る。
水分と雨のバランス再調整、水カビ・農薬・追加の資金用途は後続。
最終大会合格時の専用演出は [22_FinalClearCelebration.md](22_FinalClearCelebration.md) を参照。
人による30日間通し、別PC/GPU/DPI、長時間・過去のメモリ破損原因は今回の完了条件と分ける。
